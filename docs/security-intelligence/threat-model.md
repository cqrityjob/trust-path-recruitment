# Security Work foundation — threat model

Trust boundary: authenticated identity is shared with CQrityjob, but professional-work authorization is separate. Database administrators remain privileged operators; neither client users nor an AI worker receive those privileges.

| Threat                                                | Foundation control                                                                           | Verification / next phase                                                                                                                                         |
| ----------------------------------------------------- | -------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Anonymous access, stale identity, banned/deleted user | Real authenticated human and current active membership predicate; no anonymous grants        | Direct database role tests. Auth/session middleware remains required in B.                                                                                        |
| IDOR, employer/candidate/share-derived access         | Only `sw_workspace_memberships` grants domain access                                         | Cross-user and cross-domain relationship tests; no employer/profile foreign key authorizes reads.                                                                 |
| Cross-workspace joins or ownership reassignment       | Composite foreign keys and immutable IDs/workspace/creator columns                           | Direct malformed inserts and updates, including a user who belongs to both workspaces.                                                                            |
| Viewer/editor escalation                              | Viewer read-only, membership protected, approval separately checked                          | Positive and negative role tests, revocation takes effect without JWT refresh.                                                                                    |
| Definer abuse                                         | Helpers outside public API, pinned search path, explicit caller checks and revoked execution | Catalog checks and anonymous/service-role invocation attempts.                                                                                                    |
| Forged human approval or AI completion                | No provider execution/write surface in A; constrained human transitions                      | Unauthorized approval/status tests, source/citation/content freezing and actor checks.                                                                            |
| History tampering                                     | Trigger-generated versions/audit; no client DML                                              | Rewrite, delete and truncate privilege checks.                                                                                                                    |
| Citation spoofing or post-approval change             | Workspace FKs, immutable source facts, protected approved documents/citations                | Cross-workspace and post-approval mutation tests. Text still needs safe rendering/validation in B/C.                                                              |
| SSRF/redirects, malicious files, script injection     | No fetcher, upload bucket or parser enabled in A                                             | B must add allowlists, DNS/IP and redirect validation, byte/time/MIME limits and malicious fixtures before activation. Stored URLs confer no fetching permission. |
| Indirect prompt injection/output injection            | No model calls or AI write capability in A                                                   | C requires isolated untrusted content, strict output schemas/citations, no authority-bearing model tools and adversarial evaluations.                             |
| Denial of wallet, replay, duplicate jobs              | No paid provider or scheduled work activated                                                 | B/C must bound quotas, concurrency, attempts and idempotency before worker/provider grants.                                                                       |
| Unauthorized export or silent disclosure              | No export/sharing endpoint in A; independent domain tables                                   | C must render only a currently authorized approved version and audit explicit export; no email/publication.                                                       |
| Destructive rollback                                  | Rollback must refuse adopted workspaces                                                      | Execute refusal and empty-domain stand-down/reapply in isolated databases.                                                                                        |

Privacy: collect only the stated work purpose and needed source context. No real customer content in tests. Retention, legal holds, data-subject erasure and workspace closure need an explicit product/legal decision before accepting pilot data; immutable audit/version records must be reconciled with that policy. Do not connect to Career recommendations, CV, Passport, employment decisions or recruitment analytics.

Required in-product notice in B (equivalent Swedish/English): do not enter classified, security-protection-classified, secret or prohibited information; AI is decision support; professional judgment and approval remain human; generated conclusions need review; external sources may contain errors. No claim of classified suitability or provider training exclusion.
