This consumer is prepared for review and isolated CI. The new schema has not been installed or SQL-tested by this author: root stopped local writes during disk/Colima I/O failure. It must follow applied-schema proof before release. No production/hosted mutation, publication, AI, mail, worker, cron or generated-type edit was performed.

The private journal is created before upload, using the existing validator's own claim/period, UUID path, display name, MIME, 8 MiB ceiling and SHA256. The existing successful `EvidenceRecord` response and document-provided ceiling remain. A missing upload/attachment reply preserves the intention. Initial definite attachment refusal cleans only after the journal's transactional fence has excluded any late registration.

The merits route and Passport overview show saved own attempts after reload. Their explicit actions either download and check the original file before resuming the original attach RPC, or reconcile every evidence lifecycle and fence cleanup before owner Storage removal. Confirmed cleanup requires authenticated Storage absence plus the database's evidence/Storage-metadata absence. Unknown results and failed deletion remain recoverable; the UI disables a fresh upload while pending or while attempts cannot be read. The global view also finds intentions whose original target was deleted, including a registered record whose metadata disappeared later. No target or hash is reconstructed for older orphan files without journals.

- `scripts/passport-upload-recovery-operational.ts`: exported `verifyIsolatedUploadRecovery`. It rejects hosted targets/privileged keys before calls and requires two real `.invalid` Auth holders on an isolated loopback API and an own claim without open review. It uses normal caller JWT/anon-key SDK clients only, no fixture SQL/admin account creation. A fully successful run returns 44 labels with `kind: actual_gotrue_storage_sdk`. It checks actual lost-upload-reply recovery through a fresh client, explicit resume/exactly-one record, other-holder direct API denial, failed cleanup/reload/retry, fenced late attach/upsert, registration-first/withdrawn preservation, altered bytes, two concurrent attach/cleanup requests, then real GoTrue logout of the dedicated holder session and denial of its replayed JWT at the Passport live-session boundary. Both observed race winners are accepted only when their correct record/bytes outcome is verified. The ordinary JWT can remain cryptographically valid until TTL; this probe does not claim global instant access-token revocation.

The operational probe never prints keys/passwords/JWT, paths, bytes or bearer links. CI should retain its private run manifest bound to exact schema/app SHA and return a redacted check-label subset. Actual managed Storage transactional/race behavior, supported PG14/PG17 replay, account-erasure regression, auth expiry/reauthentication, browser reload/mobile rendering and published runtime remain mandatory release evidence. Static review and SDK stubs are not release proof. App rollback can leave the journal/fence installed; schema rollback refuses a nonempty journal so pending intentions are not discarded.
