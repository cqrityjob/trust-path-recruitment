# Native P1 bootstrap failure and status-stream correction

The first native 100-application run [37763792868](https://github.com/cqrityjob/trust-path-recruitment/actions/runs/37763792868), job `113266363377`, failed on evidence SHA `b4a27815676c2f0311d7b83007b4433d9de7b534`. Its application and schema pins were respectively `ac25b3befbfb87ed5eb682679a929708d6dfbebf` and `fd48827b79f3e09c1dc9ccb4a8720e18692d68a1`.

The preserved public artifact `11543389023` has ZIP SHA256 `4793c3a52dc4cae82cc2be7acccc6d46625af5e817e38c299707eaccc2cc323e`. Its manifest records `official_native_stack=failed`, code `P1_NATIVE_STAGE_FAILED`, an empty `serviceVersions`, and **all subsequent stages `not_run`**. The 21 guard tests passed. No schema installation, native Auth fixture, Storage fixture, 100-case oracle, API assertions or browser journey is established by this failed run. The private command logs were deliberately excluded from the artifact; the original exception was not recovered.

Code inspection found a deterministic bootstrap defect consistent with that failure boundary. The pinned [Supabase CLI 2.111.0 status implementation](https://github.com/supabase/cli/blob/v2.111.0/apps/cli-go/internal/status/status.go#L102-L115) writes stopped-service warnings to **stderr** before writing JSON to **stdout**. The runner intentionally excludes several services, while its old `command()` passed the same private file descriptor for stdout and stderr and parsed the resulting combined text as JSON. A local harmless subprocess reproduces the invalid combined JSON; this is harness evidence, not a recovered live exception or a product/schema failure.

The correction changes only the `supabase status -o json` capture. `capturePrivateOutput()` retains separate stdout and stderr files at mode `0600`, uses a 60-second timeout and a 2,000,000-byte limit per captured stream, returns stdout only, and exposes a fixed failure code without raw process output, causes or native error stacks. The existing status target/key-role guard remains required. All other commands, app/schema pins, strict history, role checks, fixtures and acceptance assertions remain unchanged.

Local checks: 24 native harness tests pass, including actual harmless subprocess JSON/warning separation, nonzero exit and stdout/stderr overflow with secrecy canaries. This local test does not start Supabase or establish any native service or product acceptance. A new ephemeral GitHub-native run is required before releasing the pending `080` schema or claiming the 100-case acceptance.
