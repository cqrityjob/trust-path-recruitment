## Concrete limitation: withdrawal does not universally stop new cases
The authoritative new-case predicate is `scp_iv_case_start_basis` (`20261108090000_beskt_governed_method_content.sql:500–540`). It tries published -> open_pilot -> active individual pilot grant at 529–536. There is **no early suspended/retired exclusion** before the grant branch. The grant predicate (`20260921090000_scp_interview_integrity_hardening.sql:553–568`) checks dates, revoked_at and cohort, not current pack content_status.
- Withdrawing open availability removes only open_pilot. A still-live grant continues to authorize the restricted draft.
- A previously granted pack later suspended/retired can still reach pilot_grant and create a new case. The case INSERT guard calls exactly that same predicate (`20270307090000:266–272`), so permanent use locks do not repair this route.
- Grant INSERT/UPDATE guard rejects published and suspended/retired packs (`20260921090000:499–508`). This forbids new grants, but does not invalidate old grants on reads; because it runs on **every** grant UPDATE, it also rejects a later revoked_at UPDATE after that version becomes published/suspended/retired. No alternative grant-revocation RPC definition was found.
- The startable list and create RPC share the predicate (`20261108090000:582–589,641–647`). This is a code-level entitlement gap, not merely a stale button.
- The latest effective create RPC is actually `20261130090000_bcp_beskt_complete.sql:1789–1795` (same predicate) and chooses internal_qa for every non-published status at 1845–1846. Neither its later content-lock patch nor the case INSERT guard adds a suspended/retired check.
- Opening an existing interview through `scp_iv_start_interview` deliberately returns the existing accessible case before new-case eligibility (20270111090000_interview_beskt_active_employer.sql:782–793). This is continuation, not a new case.
- Continuity access to pinned content is deliberately retained (`20260925090000:207–215`), and frozen case reads still enforce case ACL (`20270307090000:334`).
